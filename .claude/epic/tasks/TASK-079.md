# TASK-079: Optimize UTF-16LE string scanning in parseCodeplugRecordData

## Description

`MOTOTRBOProgrammer.parseCodeplugRecordData()` scans entire data buffers (up to 50MB) byte-by-byte looking for UTF-16LE strings. This is O(n*m) complexity and takes 500-800ms for large codeplugs.

**Current Impact:**
- Radio read operations take 30-60% longer than necessary
- Poor user experience with progress bars that stall during parsing
- Scales poorly with larger radio models (new XPR 8000 series)

---

**Completed optimizations (2026-02-17):**

### 1. Fallback UTF-16LE scan loop
- Replaced `data[offset]` subscript + `String.append(Character(UnicodeScalar(...)))` per-char with `data.withUnsafeBytes` raw pointer scan accumulating into a `[UInt8]` buffer, then one `String(bytes:encoding:.ascii)` call per run
- Replaced O(n) `channels.map { $0.name }.contains(...)` checks with pre-built `Set<String>` (`foundNameSet`) for O(1) duplicate detection
- Replaced `["talkset",...].contains { }` with a `Set<String>` (`systemStrings`) constant

### 2. parseChannelRecord
- Replaced `stride(from:to:by:1)` + `String(data:encoding:utf16LittleEndian)` at every byte with a single `Data.range(of: Data([0x02, 0x03]))` call — O(n) marker search

### 3. parseZoneRecord  
- Replaced `stride` + `Data(data[...])` allocation + `String(data:encoding:utf16LittleEndian)` at every offset with `data.withUnsafeBytes` raw scan; one `String(bytes:encoding:.ascii)` call on the first valid run

**Result:** Build clean, all 4 mock tests pass.
